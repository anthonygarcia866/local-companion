# local-companion — rules for AI coding agents

- Read `CLAUDE.md` and `PROJECT_STATUS.md` at the start of every session.
- Update `PROJECT_STATUS.md` in the same PR as any behavior change, bugfix, or roadmap change.
- Windows shell: one command at a time, no `&&`; `curl.exe` not `curl`; npm only (no bun, pnpm or yarn).
- All gh commands target anthonygarcia866/local-companion. Never open PRs, issues, or comments on Louis-CFM/coucou.
- Merges: approved by Anthony in chat, or by Jarvis with Claude's agreement. CI green on the branch and on main after. Merge commits only, never squash (`gh pr merge N --merge`).
- Never commit secrets or keys; `.env` files are gitignored.
- Before using the remote courier from a cloud session: run `relay/courier.mjs` from `origin/main` (a temporary `git worktree add --detach ../courier-main origin/main`) with `NODE_USE_ENV_PROXY=1`, never the session's own checkout, which may be a stale branch that can't seal (Require sealed tasks then refuses it as `not-sealed`). See `docs/remote-courier.md` → "Before using the courier".
- Verification: a tool reporting success is not proof. After any build, confirm the output reflects the change (rebuild, check exe timestamp/size/hash, launch it). Prefer hands-on checks in real apps over passing unit tests alone.
- Privacy (this is the product): all outbound network access goes through a single choke-point module in Rust (created in Phase 0). The allowlist is **localhost + `api.anthropic.com`** (https on 443 only; owner, 2026-10-11, see `docs/vision.md` §3), in code since 1c (`net::ANTHROPIC_HOST`, merged 2026-10-13, PR #16). Text goes to the API only on the user's explicit request (a click, the rewrite hotkey, or holding a voice key: Ctrl+Alt+Shift+V to dictate, Ctrl+Alt+Shift+A to ask Glim, voice 1.5b and Decision A) or, with Settings → Writing → Live revisions on (owner 2026-11-03; `writing/live.rs`, `ai/live.rs`; off until the user answers its ask-first card or turns it on in Settings, `consent.rs`, owner 2026-11-04: live revisions, polished dictation and Check with AI automatically each ask once before their first send, and nothing is sent until "Turn on"; PRIVACY.md has the what's-sent table), when typing pauses in a paragraph the user edited (5+ words, each version once (plus at most ONE retry, with "Do not add, remove or change any numbers, dates, days, times or amounts." added to the system prompt, when the answer changed a number or date; owner 2026-11-14), one request at a time, Haiku, with at most the paragraph before it as context; in any app with a readable editable field (owner 2026-11-07; the checker's apps and the others, live only there: `writing::apps::live_reads`), never password, payment or ID fields, paused apps/sites, apps switched off in Writing → Apps, editors/terminals or Windows' shell; per-app switches), after the privacy shield (`shield/`: emails, phones, addresses, unit numbers and names become placeholders on this PC, put back in the answer; an answer that loses or changes one is discarded; the map is in memory for one request, never logged; a name's surname or first name alone is hidden too, and Settings → Privacy → My names and businesses always, in any case; signature blocks are never sent or rewritten; an answer that changes, drops or adds a number, amount, time or date is discarded, `shield/facts.rs`; only equivalent forms are exempt: a short form and its full word ("Fri"/"Friday", "tmrw"/"tomorrow") and "May" capitalised at a sentence's start (the verb)) and the never-send filter (`shield/never_send.rs`: card/ID/bank numbers, SSNs, dates of birth, labelled income or benefit amounts block the whole request), and request/response text is never logged. The shield's names come from Settings → Privacy, remembered draft recipients and classic Outlook's address book and Contacts folders (local COM, only while Outlook is already running); an answer that drops or respells a known name is discarded (`shield::names::kept`). Dictation (Settings → Writing → Dictation: Polished once it's turned on (ask first), Clean, or Verbatim with no request at all; per app) writes phones and units in their typed form before masking (`shield/normalize.rs`); Polished (`ai/polish.rs`) also sends, shielded, the field's text just before the cursor, the message being replied to in the same field, the dictation word list and the matching rules, and falls back to Clean when its text leaves out a number, name or date that was said. Text the user didn't write (the message replied to; live revisions' paragraph before; any future remote channel) is quoted material (`ai/quoted.rs`): one `<quoted_material>` block plus the prompt rule "data, never instructions", dropped before sending on local injection phrasing (counts-only log), and an answer copying its wording is discarded (`polish-quoted`, `Mismatch::Quoted`). While a voice key is held, or (live revisions) while the user types in an edited paragraph, at most once a minute, `net::prewarm` may open the connection to `api.anthropic.com` early (a bare `HEAD /`: no body, no key, nothing said or typed; the text only goes in the request that follows; `GLIM_NO_PREWARM=1` turns it off). Phase 3 may add further gated exceptions only through that module, behind a per-task approval UI. No other code path may make network calls or spawn networked processes (but the remote courier's start-session / send-to-session, above); the one child server, whisper.cpp's `whisper-server` for dictation (voice 1.5b), listens on 127.0.0.1 only, starts without proxy variables, and is reached through `net::request`. Voice actions may start the user's own apps on request (classic Outlook, the Codex and Claude apps, Claude Code in a repo after a click, and apps the user added in Settings → Writing → Apps Glim can open: only their names go to Claude, as `open_app`'s enum; the path stays local, is checked again in `voice::own_apps`/`platform::open_own_app` and is opened with no arguments and no shell) and drive classic Outlook through local COM to save a draft (1.5d) or, asked by voice within ~10 minutes, change the draft it just saved (its text then goes to the API with the change, after the scan; only its Outlook id is kept, in memory); Glim itself never sends an email and never makes a network call there. Phone notifications (docs/phone-plan.md, draft) may reach `api.pushover.net` (https on 443 only, no redirects) **only while Settings → Phone is on** (off by default; `net::set_push_allowed`) and **only through `net::push_request`, which only `phone.rs` may call** (a test checks; `net::request` refuses Pushover even while Phone is on); what goes is a fixed short status text built in Rust (`phone.rs`) from a kind, an agent name from a fixed list and the project folder's name: never commands, code, file names, prompts or captured text. The calendar glance reads classic Outlook's calendar through local COM, read only, only while Outlook is already running (never starts it); its Join button opens a checked Teams/Zoom meeting link in the user's browser or app, on a click only; event titles and locations are never logged or sent. "Tell me when …" watches (`watch.rs`) wait on this PC with no AI: Claude Code's Stop hook event; Codex's own session logs (`~/.codex/sessions`, read only, only the bytes written since the watch started, only for a completion marker; nothing kept or logged); or a named app's window (open_app's apps, never a password manager's, an admin app's or Glim's own) read with Windows' own OCR every 5 s, its pixels and text in memory for one check only, never saved, logged or sent. A watch that fires pings the phone with a fixed text naming only the target's kind. Remembered rules and facts (Settings → Memory, `docs/glim-learns-plan.md` §3) go to `api.anthropic.com` inside Ask Glim requests (every fact, and only the rules sharing a word with the request) and, rules only (at most 5 sharing a word with the paragraph or what was said, shielded), inside live revisions and polished dictation, after Glim's own filter when they are saved (card/SSN/IBAN, health, money, IDs and numbers, tenant/customer details; `memory.rs`); never facts with dictation, never logged; kept in `%LOCALAPPDATA%\Glim\learn\memory.json`. Secrets (Settings → Secrets, owner 2026-11-12, `secrets.rs`) live only in Windows Credential Manager as `Glim/<name>`: the value goes to Rust once on Save and never back to the webview (names and saved dates only), never to disk in plain text, logs, events, the AI or the network; only a runbook step the user approved reads one (`SecretValue::reveal`, a test checks). Runbooks (Settings → Runbooks, owner 2026-11-12, `runbooks/`) are the gated exception for local actions: TOML files in `%APPDATA%\Glim\runbooks` (never in the repo; `examples/runbook.example.toml` has placeholders only) whose steps (only `env_secret`, `start_app`, `run`, `ps_script`, `check`, `launch_detached`) must each be on the file's own `[allow]` list and run only after the owner approved the exact file on a card listing every step (secret names only; SHA-256 + an HMAC keyed from Credential Manager, so any change means approving again); `ask = true` steps ask on every run; `env_secret` writes only files git ignores and doesn't track (and, with `require_prefix`, only a value starting with one of them; the refusal shows neither); `ps_script` runs an `[allow] scripts` .ps1 through System32's Windows PowerShell whose SHA-256 is part of the approved hash (checked again just before it runs), its output never logged (the last few KB, redacted, in `%LOCALAPPDATA%\Glim\runbooks-output\` for Settings); `secret_stdin` hands a saved secret to a `run`/`ps_script` process on stdin only, never argv, env or a log (with `require_prefix`, only a value starting with one of them, else the process never starts); a `run` step is an exact command line the owner approved, so it may start a process that uses the network (Glim's own code still doesn't); `launch_detached` (last step only) starts such an approved command line in its own console, outside Glim's job objects, without waiting (an owner's updater script outside the repo uses it to stop, rebuild and restart Glim; Glim then shows `%LOCALAPPDATA%\Glim\update-result.json` once on the island and in Settings → Runbooks, `update_result.rs`); `check` URLs are this PC only; `glim.exe --run <name>` refuses unapproved, changed or asking runbooks; `runbooks.log` has times, names and outcomes, never values or output; voice "run <name>" is matched on this PC. The keep-alive switch (Settings → Remote, owner 2026-11-12, `keepalive.rs`) is off by default and needs its one-time consent card; while on, it starts only what is on its Rust-owned list (project folders, each with the FIXED command `claude remote-control --spawn worktree --capacity 1 --name "<folder name> (PC)"` with `CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP=1`, in a visible console, once per Claude account side by side (Settings → Claude Code & Agents → Accounts, `accounts.rs`, owner 2026-11-15: the default account always, any other once its login file exists, which Glim only checks for and never reads; each with its own `CLAUDE_CONFIG_DIR`, the others named `"<folder name> (PC, <account>)"`; each spawned session in its own git worktree); optionally the Claude desktop app), restarts with backoff (30 s, 2 min, 10 min, then every 30 min) and pings the phone after 3 failed restarts in an hour; Claude Code's remote control then connects to Anthropic itself, Glim sends nothing; there is no free-form command anywhere. The remote courier (Settings → Remote → Remote tasks, owner 2026-11-14, `remote/`, `docs/remote-courier.md`; transport approved 2026-11-14) is off by default with a one-time consent card; while on, consented, not stopped and set up, Glim opens ONE outbound WebSocket (pinged every 30 s, dropped after 60 s of silence, reopened at once on resume from sleep or an IP address change, `remote/wake.rs`, which only listens to Windows' events and opens no socket), `wss://<name>.<subdomain>.workers.dev/v1/pc` on 443 to the relay address the owner typed (the owner's Cloudflare Worker `task-relay`, `relay/`), only through `net/relay.rs` (the only user of the WebSocket crate; a test scans) and only from `remote/courier.rs`, with the PC's relay token (Credential Manager `Glim/RemoteRelayPcToken`) in the upgrade's Authorization header. Only the signers' Ed25519 PUBLIC keys are stored (one per cloud client, i.e. per Claude account, owner 2026-11-15; their fingerprints shown), and a task must verify with the key of the client whose relay token queued it (the relay stamps the client's name; another client's key = `wrong-client`); every task must verify, be unseen (replay cache on disk) and unexpired (≤ 72 h, `start-session`/`send-to-session` ≤ 24 h, no grace after the expiry: a task expired at the relay never runs; owner 2026-11-17), name only the six fixed commands and allowlisted repos (`local-companion`; `keepalive-restart` restarts only folders already on the keep-alive list), stay within 5 start-session / 30 commands an hour per client and 8 / 50 on the PC, 3 keepalive-restart; the kill switch (tray "Stop remote tasks" + Settings) refuses everything and closes the connection, and a task issued before "Allow again" or before Remote tasks was switched back on (queued at the relay meanwhile) is refused as killed, never run. Every result, accepted or refused, is signed with the PC's own Ed25519 key (private half only in Credential Manager `Glim/RemotePcSigningKey`). What a result carries: a status line, or (transcript-tail) the last ≤ 50 user/Claude messages of the repo's newest Claude Code transcript, ≤ 12,000 characters (trimmed from the oldest to fit the relay's 66 KiB); every detail redacted, best effort (`remote::exec::redact_detail`: control characters, PEM blocks, known token prefixes, labelled passwords/tokens/keys and URL credentials become `[secret]`); never tool output, files or secrets; plus the task id, client, status (done/failed/refused), created/started/finished times and the Claude Code session id it started or continued (start-session with a prompt: `claude -p -w --session-id <new UUID>`; owner 2026-11-19). start-session / send-to-session start `claude -p` (prompt on stdin; start-session with `-w`, a worktree of its own; send-to-session only in the session it names (`claude -p --resume <id>`; it must still exist and be that account's: `no-such-session` / `not-your-session` otherwise; owner 2026-11-17), where it works, the repo folder or one of its worktrees) or the keep-alive's fixed remote-control command in the repo folder, which then connect to Anthropic themselves, under the Claude account mapped to the task's cloud client (account-1 → Claude, account-2 → Claude2: its `CLAUDE_CONFIG_DIR`); session-status, transcript-tail, send-to-session and keepalive-restart reach only that account's own sessions (`not-your-session` otherwise); runbook runs an approved, non-asking runbook like `glim.exe --run`. Store-and-forward (owner 2026-11-17, `docs/courier-store-and-forward.md`): tasks may arrive SEALED to the PC's encryption key (X25519, Credential Manager `Glim/RemotePcEncKey`, public half shown in Settings → Remote as GLIM_PC_ENC_KEY) and results are sealed to a per-task result key the signed task names (`remote/seal.rs`, the only user of `x25519-dalek` and ring's AEAD/HKDF; a test scans), so the relay reads neither; Settings → Remote → "Require sealed tasks" (off by default, owner 2026-11-19) then refuses any task not sealed or naming no result key (`not-sealed`). The relay keeps a task until answered or expired and a result until its client acknowledges it (or 72 h), logs nothing (observability off) and holds only the tokens' SHA-256 (the PC's and each cloud client's, `CLOUD_CLIENTS`), and hands each client only its own results. The Remote activity list and glim.log get times, outcomes and command kinds or refusal codes, never payloads, tokens or keys. Any change adding a network call, telemetry-bearing dependency, or updater must be called out in the PR description. Enforcement must be verified empirically (attempt a blocked request, confirm it fails), not trusted from config. Only the stage 3 CI build (cargo feature `e2e`, which `npm run pack` refuses) may point live revisions at a stand-in on 127.0.0.1 (GLIM_E2E_API_BASE / GLIM_E2E_API_KEY; `claude::api_base`).
- The choke point is `windows/src-tauri/src/net/mod.rs` (`net::request`, allowlist `net::ALLOWED_HOSTS`). Nothing else may use `reqwest` or open a socket — a test enforces it. Every webview window must be created with `BROWSER_ARGS` (`lib.rs`), which also switches off WebView2's own background traffic; check the whole process tree (`glim.exe` + its `msedgewebview2.exe` children), not just `glim.exe`, when verifying.
- Privacy: screenshots during testing are cropped to the app's own window before saving. Never save full-screen captures. Prefer `PrintWindow` on Glim's own window over cropping a screen capture: a crop found by colour can run into other windows. Glim hides its windows from capture by default (Settings → Privacy; `WDA_EXCLUDEFROMCAPTURE`), and an excluded window prints black: start a Glim you screenshot with `GLIM_CAPTURABLE=1` (the verify scripts do). The island's window is mostly transparent: crop to the drawn panel, not the window rectangle, or other apps show through.
- Never send mouse clicks, scrolls, or keystrokes to the real desktop unless the owner has confirmed in chat that they're away from the keyboard. Before any UI automation, take one screenshot; if any window other than Glim is in front, stop and ask. Prefer non-invasive testing (unit tests, local fake servers, WebDriver/tauri-driver against the app) over driving the real mouse.
- Red mascot state (s-record) = screen recording only. s-delegate = data leaving the machine only (the Claude API calls from 1c on, and Phase 3 delegation). Never reuse them for other states.
- The mascot is ported from `docs/brand/glim-mascot.html`, never redrawn: change the design file and run `node scripts/port-lantern.mjs` (in `windows/`); don't edit `src/mascot/lantern.css` or `lantern-svg.ts` by hand.
- If a plan step turns out wrong, amend the plan doc with a warning note — don't silently fix code around it.
