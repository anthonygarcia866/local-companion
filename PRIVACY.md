# Privacy

Glim is local-only. In Phases 0–2 nothing it does leaves this computer. This file says what is enforced, and where in the code, so each claim can be checked.

## What is enforced, and where

| Rule | Where | How it is checked |
|---|---|---|
| Every outbound HTTP request goes through one module. | `windows/src-tauri/src/net/mod.rs` | `net::tests::no_other_module_can_reach_the_network` scans every Rust source file outside `src/net/` and fails if one names `reqwest`, `TcpStream`, `TcpListener`, `UdpSocket`, `tokio::net::Tcp*/Udp*`, `ToSocketAddrs`, `WinHttp`, `WinInet` or `URLDownloadToFile`. |
| Only `127.0.0.1` and `localhost` (any port, http or https, no credentials in the URL) are allowed. Anything else — another host, a LAN address, `::1`, `0.0.0.0`, other `127.x` addresses, `*.localhost` — is refused before a socket opens. | `net::ALLOWED_HOSTS`, `net::check`, `net::request` | `only_127_0_0_1_and_localhost_are_allowed`; `a_request_to_an_external_host_is_refused_before_anything_is_sent` tries `https://example.com` through the real request path and expects the refusal. |
| A redirect may only lead to another allowed address. | `net::request` (custom redirect policy) | `a_redirect_off_this_machine_is_refused` serves a real `302 → https://example.com` on loopback and expects the request to fail. |
| No proxy is ever used (a system or `HTTP_PROXY` proxy would carry the request off the machine). | `net::request` (`no_proxy()`) | `a_system_proxy_is_never_used` sets `HTTP_PROXY`/`ALL_PROXY` to a fake proxy and checks the answer came straight from the local server. |
| `localhost` resolves to `127.0.0.1` inside the app, whatever the hosts file says. | `net::request` (`resolve("localhost", 127.0.0.1)`) | — |
| A model server address typed in Settings is refused unless it is on this machine. | `net::normalise_server_url` (called by `local_chat.rs`) | `a_pasted_server_address_is_cleaned_up`, `connect_cleans_a_pasted_address_and_reports_whether_it_is_this_machine` |
| The webviews can only fetch from the app itself, the IPC bridge, and loopback. | `windows/src-tauri/tauri.conf.json` → `app.security.csp`: `connect-src ipc: http://ipc.localhost http://127.0.0.1:* http://localhost:*` (plus `object-src 'none'`, `form-action 'none'`, `frame-src 'none'`) | — |
| The WebView2 runtime makes no background connections: no Edge experiment config, component updater, network-error reports, pings or proxy auto-discovery, and no host name but `localhost` resolves inside the webview. | `BROWSER_ARGS` in `windows/src-tauri/src/lib.rs` and `additionalBrowserArgs` in `tauri.conf.json`: `--disable-background-networking --disable-component-update --disable-domain-reliability --no-pings --no-proxy-server "--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE localhost, EXCLUDE *.localhost"` | `every_window_asks_webview2_for_the_same_locked_down_arguments` keeps both copies identical and the switches present. Observed with netstat and a WebView2 net-log (2026-10-09): without them the runtime called `config.edge.skype.com`, `edge.microsoft.com` and `ecs.nel.measure.office.net`; with them, nothing. |
| "Open in browser" only opens loopback pages. | `open_url` in `windows/src-tauri/src/lib.rs` → `net::check_str` | — |
| Glim's windows are left out of screen shares, recordings and screenshots (Settings → Privacy, on by default). | `screen_capture.rs` → `platform::set_capture_excluded` (`WDA_EXCLUDEFROMCAPTURE`) on every window at launch, on each new window and on each save; `GLIM_CAPTURABLE=1` turns it off for tests | `a_window_of_our_own_is_excluded_from_capture_and_let_back_in` reads the affinity back; `every_window_glim_builds_is_covered` |
| While a voice key is held, Glim may open its connection to `api.anthropic.com` early, so the answer comes sooner. What goes out is a bare `HEAD /`: no body, no API key, none of Glim's headers, nothing the user said. The transcript only goes in the request after the key is released, on that same connection. `GLIM_NO_PREWARM=1` turns it off. | `net::prewarm` (only the Claude API's origin), started by `voice::run::start_prewarm` | `a_prewarm_sends_nothing_and_the_request_reuses_its_connection`, `a_key_released_fast_still_gets_its_answer`, `only_the_claude_api_is_prewarmed` |
| "Tell me when …" watches never use AI while waiting and keep nothing. A window watch reads that app's window with PrintWindow + Windows' own OCR every 5 s, in memory for one check, never saved, logged or sent; never a password manager's, an admin app's or Glim's own window. A Codex watch reads only the new bytes of Codex's session logs, looking only for its completion marker. The phone ping is a fixed text with the target's kind only. | `watch.rs`, `platform::ocr_window` / `app_window`, `phone::Kind::Watch` | `watch::tests::*` (each target with fakes; the log never carries what was read), `phone::tests::a_watch_ping_is_fixed_text_and_follows_the_away_and_quiet_rules` |
| **Privacy shield** (Settings → Privacy, on by default; owner, 2026-11-03). Before any of the user's text goes to Claude (the rewrite, "Check with AI", dictation's clean-up, Ask Glim and a draft's change), emails (written or spoken), phone numbers, street addresses, unit numbers and people's names are swapped on this PC for numbered placeholders (`[PERSON1]`, `[EMAIL1]`, `[PHONE1]`, `[ADDRESS1]`, `[UNIT1]`). Names come from Settings → Privacy's list, the recipients remembered from "Draft email" cards and classic Outlook's address book and Contacts folders (a contact with no email address is in no address list, so its full, first and last name and company are read from Contacts too), read through local COM only while Outlook is already running (never started). And whatever was masked: an answer (revision, rewrite, polished dictation) in which a known name of the text is missing or spelled differently is discarded (`shield::names::kept`; the log gets counts only). The real values go back into the answer before anything is shown or typed; a rewritten text (rewrite, dictated text) whose placeholders are missing, doubled or changed is discarded, and any answer with a changed or made-up placeholder is discarded. The placeholder map lives in memory for one request; it is never logged, stored or sent (its Debug shows counts only). A name's surname or first name alone is hidden too when written with a capital or in capitals ("Smith", "Mr. Smith", "SMITH"); in lower case only when it comes from the user's own lists; a name word that is also a common word ("Carter") only after Mr., Ms., Mrs., Dr. or Mx. | **Live revisions** (Settings → Writing; owner, 2026-11-03; off until the user says yes on its ask-first card or in Settings, 2026-11-04). When typing pauses (1.5 s by default, 1-3 s) in a paragraph the user edited (5+ words, each version once, one request at a time), that paragraph, at most the paragraph before it and up to 5 remembered rules sharing a word with it go to Claude Haiku through the privacy shield and the never-send filter. In any app with a readable editable text field (owner, 2026-11-07), not only the writing checker's apps; never in password, payment or ID fields, paused apps or sites, an app switched off in Settings → Writing → Apps, code editors and terminals, or Windows' own shell (Start search, the lock screen); and only in apps whose Live revisions switch is on. In an app the checker is off for, the field is read for live revisions only (nothing is checked or listed) and the accept key copies the revision instead of typing it. A paragraph that looks like it holds a key, token or password (a PEM block, a known key prefix, a labelled password, a long run of letters and digits) is never sent. While the user types, the connection may be opened early, at most once a minute (a bare `HEAD /`, no text, no key; `GLIM_NO_PREWARM=1` turns it off). The log gets codes, timings and cost only. | `writing/live.rs` (when, stale and too-different answers), `ai/live.rs` (the request), `capture/uia.rs` (`Request::Live`) | `writing::live::tests::*` (pause, edited only, 5 words, switches, one in flight, stale, > 60 % dropped, hidden on typing), `ai::live::tests::*` (the request, shielded, never-send, the log has no text) |
| **Polished dictation** (Settings → Writing → Dictation; owner, 2026-11-03; Clean until the user says yes on its ask-first card or picks Polished, 2026-11-04). Besides the transcript, a Polished request carries the field's text just before the cursor (up to 800 characters), the message being replied to when it is in the same field (up to 1,500), the dictation word list and up to 5 remembered rules sharing a word with what was said; all through the privacy shield and the never-send filter, read from the field when the key goes down and kept in memory for that one dictation. Clean sends the transcript as before; **Verbatim sends nothing**. | `ai/polish.rs`, `voice::set_field_context` (capture thread), `voice/run.rs` `clean_up_app` | `ai::polish::tests::*` (the request, the shield, the detail check, never-send), `writing::live::tests::polished_dictation_gets_the_text_before_and_the_message_replied_to` |
| **Never-send filter.** A request is not sent at all when it holds a card, ID or bank number (Luhn-valid cards, SSN-shaped numbers, IBANs, long digit runs), an SSN after its label, a date of birth after its label ("DOB", "date of birth", "born on" …; stricter than "next to a name": any labelled date of birth), or an income or benefit amount labelled as such ("income", "salary", "wages", "SSI", "SNAP", "child support" … within six words of a dollar amount). | `shield/never_send.rs`, checked on the whole request body by `claude::blocked` inside `claude::send` (every Claude request) | `shield::tests::never_send_blocks_numbers_ssns_birth_dates_and_income` (and what stays sendable: rent, fees, unit lists, birthdays), `claude::tests::the_never_send_filter_refuses_ssns_birth_dates_and_income_too` (nothing reaches the network) |

## Ask first: what each cloud feature sends (owner, 2026-11-04)

Live revisions, polished dictation and "Check with AI automatically" send text by themselves, so each starts **off**. The first time one would send, nothing is sent: the island shows a one-time card with exactly what that feature sends (the rows below), and "Turn on" / "Not now". Only "Turn on" (or the feature's switch in Settings, which shows the same answer) lets it send; "Not now" keeps it off and the card doesn't come back by itself. A manual rewrite, a "Check with AI" click, holding the dictation key (Clean) and Ask Glim are the user asking, so they need no card. Every send shows the lantern's data-leaving look (s-delegate). `consent.rs`, `core/consent.ts`, `views/consent.ts`; tests `consent::tests::*`, `settings-writing.test.mjs`, `dictation-levels.test.mjs`.

| Feature | What is sent (only to `api.anthropic.com`, after the shield and the never-send filter) | Never sent |
|---|---|---|
| **Live revisions** | The paragraph being edited, when typing pauses (5+ words, each version once); the paragraph before it, for context; up to 5 remembered rules sharing a word with it | Signature blocks; password, payment and ID fields; paused apps and sites; anything the never-send filter refuses |
| **Polished dictation** | What was said, in its typed form; the field's text just before the cursor; the message being replied to in that field; the dictation word list; up to 5 matching remembered rules. Until it's on, dictation is Clean (what was said only) | Signature blocks in the context; remembered facts |
| **Check with AI automatically** | The paragraph being typed in, after a 2-second pause, once per version | Signature blocks; the same fields and apps as above |

In every row, names (address book, remembered recipients, the user's lists, My names and businesses), emails, phone numbers, addresses and unit numbers are placeholders on this PC first; an answer that changes a placeholder, or a number, amount, time or date, is discarded.

## What was removed in Phase 0a

- Cloud chat providers: Anthropic, OpenAI, Google AI, OpenRouter, and the "any OpenAI-compatible server" option (which could point anywhere), with their API-key storage in the Windows Credential Manager.
- Web-service pollers: GitHub, Stripe, Vercel, Notion, Resend, Cal.com, n8n.
- The Codex plan pill, which ran `codex app-server` (a process that asks OpenAI's service for the plan limits).
- The domain-directory lookup of the user's display name (`GetUserNameExW`), which can query a domain controller. Only the local account database is read now.

## What still talks to other processes on this machine

- **Agents' hooks** (Claude Code, Codex, Cursor, Gemini CLI, Copilot CLI, Muse Code, OpenCode, Amp, Hermes): the agent runs the relay `glim-hook.exe` on each event, and the relay forwards the event to Glim over a named pipe `\\.\pipe\glim-<user SID>`. Nothing in this path is networked. Details in `PROJECT_STATUS.md` → "Claude Code integration".
- **Ollama / LM Studio** on `127.0.0.1`. If you point `OLLAMA_HOST` at another machine, the allowlist refuses it.
- **The clipboard, for one paste** (2026-11-05, changed 2026-11-06): accepting a live revision or Rewrite's **Use this** puts the new paragraph in as one undo step. In Word the clipboard isn't used at all: the paragraph goes in through Word's object model on this PC (`capture/word_om.rs`). In classic Outlook too (2026-11-07: Outlook ignores a simulated paste). In other apps it is one paste: Glim first copies the whole clipboard into memory (every format, byte for byte; when it holds something that can't be put back exactly, such as a picture, the paragraph is typed instead and the clipboard is never touched), keeps it for about two seconds, and puts it back once the paste has landed, unless you copied something new meanwhile; it is never logged, stored or sent. Glim's own paste is marked so Windows keeps it out of clipboard history (Win+V) and the cloud clipboard, and carries a Glim mark: if Glim is stopped mid-paste, the next start clears it, so Glim's text never stays on the clipboard (`capture/fix.rs`).
- **Launching other apps on request**: "Open terminal" brings the session's terminal forward or opens VS Code (`code`), the Claude Desktop pill opens the Claude app, and "Show folder" opens Explorer. Those apps are separate programs with their own network behaviour; Glim only starts or focuses them when you click.

## Not covered by the choke point

- The **build** downloads Rust crates, npm packages, and the NSIS/WiX installers (Tauri bundler) — build time only, never at runtime.
- The **WebView2 runtime** is Microsoft's component and is updated by Microsoft's own updater service, outside Glim's processes. Inside Glim's processes its background traffic is switched off (table above) — checked empirically, not assumed (see `PROJECT_STATUS.md` → "Phase 0a verification"). A future runtime version could add a service those switches don't cover; the host-resolver rule is the backstop for anything that uses a host name.
- **Your own status line command**: if you install the plan-usage relay and you already had a Claude Code status line, the relay runs that command for you, as Claude Code would. What it does is up to it.
